# Original semaphore bounded reservation state

This suite targets actual `WASemaphore.Semaphore` instances, `availablePermits`, `acquire` and one immediately invoked original permit `release` per reservation case. Thirty-three cases contain 435 probes per source revision, with at most 35 probes, 17 retained objects or two pending handles per case. All 34 tests passed against actual archived sources at `1051710191` and `1051908825` through the local core Subject, including unchanged comparisons. The run used explicit diagnostic process mode (`isolated:false`) with runtime source digest `7609874cb9622bf1d7df6146b123b3a25618ae5217d4cc139bda3e2eca5fab6f`; this is partial reservation coverage.

Each reservation case first acquires a real permit, retains that returned object and invokes its original release immediately. Availability must return to its initial value. Later acquisitions retain the real returned objects and compare their identity with that earlier released marker. Those false identity results are paired with positive counter-decrement observations as capacity is consumed. Object distinction alone is not whole permit-interface or branding proof.

Default and explicit-undefined constructors are covered. Generated positive integer capacities 1 through 16 use external reservation counts. Separate literal tables characterize fractional capacities, numeric strings, a boolean and a numeric array, including selected negative remaining counts for fractional values. These inputs characterize the source's coercive behavior, not a positive-integer specification or an exhaustive numeric domain.

Separate no-reference cases start and inspect two bounded unresolved acquisitions for zero, negative, NaN, null, false and nonnumeric capacities. They never await an unresolved handle. Pending and retained-reference controls remain incompatible across a whole case. A new case constructs a fresh source instance; that is not an invented reset, disposal or process-restart API.

The full declared graph at both pins contains seven present primary modules and missing `cr:6640`, totaling 30,747 printed bytes. Analyzer v4 finishes within its unchanged default work budget at 135,074 units, finding no recognized gates while preserving the missing provider diagnostic. The explicit null fixture selects the actual Promise module's realm-native fallback. It does not establish the unknown original conditional provider, its domains/bootstrap or complete original configuration acceptance.

Later release of a held permit after intervening probes is still blocked: current controls do not expose a later callable selector for a retained permit. The suite does not bypass this through internal helpers, property selectors, callbacks, fake permits or a fabricated factory. Queue fulfillment/FIFO, double-release errors, cancellation, fairness, full permit interfaces, concurrency/interleavings and full semaphore lifecycle remain unaccepted.

No browser/native/account/network/storage/crypto provider, container isolation, production scheduling, calling/WASM or named-library behavior is accepted.
