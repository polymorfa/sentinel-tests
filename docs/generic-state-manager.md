# Original generic state manager and internal waiters

This suite targets actual `WAGenericStateManager` instances and the real `WAPubSub.simplePubSub` used internally by `waitForValue`. Seventeen cases contain 437 probes per revision, with at most 82 probes and five pending handles per case. The focused archived-source check passed 18 tests, including portable validation and all source cases at both pins through the reviewed generic core adapter. Execution used diagnostic process mode, `isolated:false`; it is not container or production acceptance.

The cases cover primitive and structured state reads/replacements, repeated sets, already-current immediate waits, multiple waiters for the same and different values, skipped targets and later return to a target. Literal null/undefined/boolean/number/string boundaries characterize the original strict equality check. Three generated 18-update histories compare settlement against an independent first-seen-target record. No subscriber, callback, readiness implementation or rejection policy is supplied by the suite.

NaN does not equal itself, so a NaN waiter remains pending through the bounded history even when the current or published value is NaN. A separate case observes a fresh structurally equal object target remaining pending after fresh equal-looking updates. These waits are inspected, never awaited indefinitely; no cancellation, disposal or listener-count cleanup claim follows. Runtime observations occur at native microtask checkpoints and do not establish every possible task schedule or subscriber delivery order.

A separate no-pending history retains genuine constructor-held and `set`/`get` returned state objects, checks their identity, and restores earlier actual objects. Pending and retained-reference controls remain case-wide incompatible. The suite does not test waiting for a retained same-object target and does not mutate previously retained data in place. Signed zero is not claimed through the existing JSON number transport.

These are generic state/waiter observations, not history/model/connection application behavior. Direct keyed pubsub APIs, external subscriber exceptions/reentrancy, timers, process restarts, account/network/storage/crypto providers, original browser bootstrap, container isolation, production scheduling and named-library acceptance remain outside scope.
